## T-003 — Управление визитками: создание, список, редактирование

### Статус
Ready

### Цель
Авторизованный пользователь может создавать и редактировать свои цифровые визитки,
просматривать их список и управлять статусом публикации.

### Предусловия
- T-001 — инфраструктура проекта завершена.
- T-002 — авторизация завершена и проверена.
- Защищённые API endpoints могут получить `currentUser.id`.

### Scope
- Модель `Card`.
- Модель `CardLink`.
- Prisma migration для карточек и ссылок.
- API для создания карточки.
- API для списка карточек текущего пользователя.
- API для получения одной карточки владельцем.
- API для редактирования карточки.
- API для публикации и снятия с публикации.
- API для архивирования и удаления карточки.
- Генерация уникального slug.
- Базовые страницы:
  - `/dashboard`
  - `/cards/new`
  - `/cards/[id]/edit`
- Валидация данных карточки.
- Unit- и integration-тесты.

### Вне scope
- Публичная страница карточки.
- QR-код.
- vCard.
- Загрузка фотографий.
- Аналитика.
- Выбор и генерация шаблонов.
- AI-функции.
- NFC.
- Корпоративные карточки и роли сотрудников.
- Оплата и тарифы.

### Поля карточки
- `displayName` — обязательное имя владельца.
- `jobTitle` — необязательная должность.
- `companyName` — необязательное название компании.
- `summary` — необязательное краткое описание.
- `phone` — необязательный телефон.
- `email` — необязательный e-mail.
- `showEmail` — по умолчанию `false`.
- `websiteUrl` — необязательная ссылка на сайт.
- `photoUrl` — nullable; загрузка файлов не реализуется в этой задаче.
- `slug` — уникальный публичный идентификатор.
- `status` — `draft`, `published`, `archived`.
- `links` — список внешних ссылок.

### Правила slug
- Допустимы только строчные латинские буквы, цифры и дефис.
- Длина: от 6 до 32 символов.
- Slug уникален без учёта регистра.
- Если пользователь не указал slug, система генерирует его из имени и случайного суффикса.
- Если выбранный slug занят, система возвращает `409 SLUG_ALREADY_EXISTS`.
- Slug карточки не меняется автоматически при редактировании имени.

### Acceptance criteria

#### Создание
- [ ] Авторизованный пользователь может создать карточку.
- [ ] Неавторизованный запрос на создание возвращает `401`.
- [ ] Обязательное поле `displayName` валидируется.
- [ ] Новая карточка создаётся со статусом `draft`.
- [ ] `showEmail` по умолчанию равен `false`.
- [ ] Если slug не задан, он генерируется автоматически.
- [ ] Повторяющийся slug возвращает `409 SLUG_ALREADY_EXISTS`.
- [ ] Ссылки карточки сохраняются в заданном порядке.

#### Список и чтение
- [ ] Пользователь получает только свои карточки.
- [ ] Список карточек поддерживает пагинацию.
- [ ] Авторизованный пользователь может получить данные своей карточки для редактирования.
- [ ] Запрос карточки другого пользователя возвращает `404`.
- [ ] Неавторизованный запрос возвращает `401`.

#### Редактирование
- [ ] Владелец может менять поля своей карточки.
- [ ] Изменение имени не меняет slug автоматически.
- [ ] Владелец может изменить slug, если новый slug валиден и свободен.
- [ ] Пользователь не может редактировать карточку другого пользователя.
- [ ] Пользователь не может передать `userId` и присвоить карточку другому аккаунту.
- [ ] `showEmail` сохраняется и возвращается в приватном API владельца.

#### Статусы
- [ ] Владелец может опубликовать карточку.
- [ ] Владелец может снять карточку с публикации, вернув её в `draft`.
- [ ] Владелец может архивировать карточку.
- [ ] Невалидный статус отклоняется с `400 VALIDATION_ERROR`.

#### Удаление
- [ ] Удаление выполняется как soft delete.
- [ ] Удалённая карточка не появляется в обычном списке.
- [ ] Удалённая карточка не доступна для редактирования.
- [ ] Связанные CardLink удаляются или каскадно помечаются удалёнными согласно модели данных.

#### Тесты
- [ ] Есть тесты на создание, чтение, редактирование и удаление.
- [ ] Есть тесты на доступ двух разных пользователей к карточкам друг друга.
- [ ] Есть тесты на уникальность и формат slug.
- [ ] Есть тесты на скрытие/сохранение `showEmail`.
- [ ] Тесты проверяют недоверенные поля и mass assignment.

### Definition of Done
- [ ] Prisma migration применяется на чистой тестовой БД.
- [ ] Все endpoints документированы в OpenAPI.
- [ ] Все DTO валидируются.
- [ ] Проверка владения карточкой выполняется на backend.
- [ ] `npm run lint` проходит.
- [ ] `npm run test` проходит.
- [ ] UI позволяет создать карточку и увидеть её в кабинете.
- [ ] UI показывает ошибки валидации и состояния загрузки.

## T-004 — Публичная страница визитки

### Статус
Ready

### Цель
Получатель открывает опубликованную визитку по ссылке `/u/{slug}`
без регистрации и установки приложения, видит разрешённые владельцем
данные и может воспользоваться доступными каналами связи.

### Предусловия
- T-003 завершена.
- Владелец может создать, изменить и опубликовать карточку.
- В модели Card существуют slug, статус публикации и признак удаления.
- Реализованы CardLink и порядок отображения ссылок.

### Scope
- Публичный API получения опубликованной карточки.
- Отдельный публичный DTO с явным списком разрешённых полей.
- Страница `/u/[slug]`.
- Один базовый адаптивный шаблон.
- Кнопки телефона, e-mail, сайта и ссылки из CardLink.
- Скрытие незаполненных полей.
- Скрытие e-mail при showEmail=false.
- Обработка недоступной карточки и ошибок API.
- Базовые metadata и canonical URL.
- Кнопки «Открыть визитку» и «Копировать ссылку» в кабинете владельца.
- Integration- и E2E-тесты.

### Вне scope
- QR-код.
- vCard и кнопка «Сохранить контакт».
- Сбор просмотров и кликов.
- Дашборд аналитики.
- Загрузка изображений.
- Офлайн-доступ и service worker.
- Выбор шаблонов, темы и AI-дизайн.
- Каталог визиток и поиск.
- Новые OAuth-провайдеры.
- Изменения архитектуры авторизации.

### Продуктовые решения для этой задачи
- Публично доступна только карточка со статусом published,
  не помеченная удалённой.
- Для draft, archived, deleted и неизвестного slug возвращается
  одинаковый ответ 404 без раскрытия причины.
- После снятия с публикации следующий новый запрос страницы
  не должен возвращать ранее опубликованную карточку.
- Старую вкладку браузера принудительно не очищаем:
  уже переданные данные невозможно отозвать.
- В этой задаче публичные карточки не индексируются:
  robots = noindex, nofollow.
- Доступ по ссылке не является защитой конфиденциальных данных:
  любая опубликованная информация доступна получателю ссылки.
- Публичный API и страница работают без пользовательской сессии.

### Публичный API

GET /api/v1/public/cards/{slug}

#### Успешный ответ: 200
{
  "card": {
    "slug": "ivan-ivanov",
    "displayName": "Иван Иванов",
    "jobTitle": "Руководитель проектов",
    "companyName": "Компания",
    "summary": "Цифровизация логистики",
    "photoUrl": null,
    "phone": "+79990000000",
    "email": null,
    "websiteUrl": "https://example.ru",
    "links": [
      {
        "type": "telegram",
        "label": "Telegram",
        "url": "https://t.me/example"
      }
    ]
  }
}

#### Правила ответа
- Использовать отдельный PublicCardDto.
- Сериализовать только явно перечисленные публичные поля.
- При showEmail=false поле email всегда равно null.
- Не возвращать userId, e-mail аккаунта, identities,
  внутренние служебные поля и данные сессии.
- Не возвращать запись Prisma через spread или напрямую.
- Ссылки возвращаются в порядке sortOrder.
- Неизвестная или недоступная карточка возвращает 404 CARD_NOT_FOUND.
- Некорректный slug возвращает тот же 404.
- Публичные ответы: Cache-Control: no-store.
- Не устанавливать auth cookies из этого endpoint.

### Страница `/u/[slug]`

#### Отображение
- Имя — главный заголовок.
- Должность, компания и описание — только если заполнены.
- Фото — только при наличии допустимого источника.
- Если фото отсутствует или не загрузилось — нейтральный placeholder.
- Длинные строки и ссылки не создают горизонтальную прокрутку.
- Пользовательский текст отображается как текст, не HTML.

#### Действия
- Телефон: ссылка tel:.
- E-mail: ссылка mailto:, только если публичный email не null.
- Сайт: валидная внешняя ссылка.
- CardLink: валидная внешняя ссылка с понятным названием.
- Внешние HTTP(S)-ссылки открываются в новой вкладке
  с rel="noopener noreferrer".
- Для tel: и mailto: новая вкладка не требуется.
- При отсутствии контактов блок действий не отображается.
- Не добавлять кнопки QR, vCard и аналитики.

#### Состояния
- Успешная загрузка.
- Карточка недоступна: понятная страница «Визитка не найдена».
- Временная ошибка API: отдельное сообщение об ошибке,
  а не ложный 404.
- Ошибка изображения не блокирует остальные данные.

### Рендеринг и кэширование
- Основная информация формируется на сервере.
- Не использовать приватный API владельца для публичной страницы.
- Не передавать пользовательские cookies и Authorization
  в публичный запрос.
- Для T-004 не использовать ISR, статическую генерацию карточек
  и межзапросный кэш их данных.
- Явно отключить кэширование публичных данных и страницы
  способом, совместимым с установленной версией Next.js.
- Не менять версию Next.js ради реализации этой задачи.
- Повторное открытие страницы после редактирования
  показывает актуальные данные.
- После изменения showEmail с true на false новый запрос
  не содержит старый e-mail.

### Metadata
- title: имя владельца и название продукта.
- description: краткое описание либо нейтральный текст
  без телефонов и e-mail.
- canonical: абсолютный URL `/u/{slug}` на основном домене продукта.
- robots: noindex, nofollow.
- Metadata формируется только из публичного DTO.
- Скрытый e-mail не должен попадать в metadata.

### Изменения кабинета владельца
- Для опубликованной карточки доступны:
  - «Открыть визитку».
  - «Копировать ссылку».
- Для неопубликованной карточки не показывать ссылку
  как работающую публичную страницу.
- При ошибке Clipboard API показать ссылку для ручного копирования.
- После копирования показать доступное текстовое подтверждение.
- URL формируется из настроенного публичного адреса продукта,
  а не внутреннего адреса API.

#### Доступность
- [ ] Опубликованная карточка открывается без входа в аккаунт.
